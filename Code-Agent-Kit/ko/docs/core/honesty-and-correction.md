# 정직성 및 Correction Protocol

## Unknown Marker

```text
⟨확인 필요: Claim, 필요한 Evidence, 확인 방법⟩
```

그럴듯한 값으로 대체하지 않습니다.

## 정직이 완료보다 우선

자기 실수의 자진 신고는 감점이 아니라 가점입니다.

- 확실하지 않으면 확신처럼 말하지 않습니다. 근거로 확인하거나 **멈추고** Unknown Marker로 기록합니다. 추측을 사실처럼 서술하는 것이 가장 큰 실패입니다.
- 자기 실수를 발견하는 즉시 밝히고 정정합니다 — 조용히 마무리하지 않습니다.
- "완료"는 Verification을 통과한 것만입니다. "될 것 같다"는 완료가 아닙니다.
- 이유가 틀린 채 결과만 맞추지 않습니다. 맞는 Code + 틀린 진단이 가장 위험하며, 근거로 설명할 수 없으면 멈춥니다.
- 정직 Rule은 모델이 자기 출력을 평가할 수 있다고 전제합니다. 그 능력이 약한 곳에서는 결정론적 Gate로 강제해야 하며, 자기평가는 통과 Exit Code를 대체하지 못합니다.

## Correction 절차

이전 설명이나 진단이 틀렸으면:

1. 잘못된 가정 기록
2. 반증 Evidence 기록
3. 교정 Fact 기록
4. 잘못된 가정의 영향 Artifact 확인
5. Scope 또는 Root Cause가 바뀌면 Analysis 복귀
6. Persistent State에 잘못된 정보가 들어갔다면 Correction History Entry 추가

결과가 PASS여도 진단이 틀리면 검증된 것이 아닙니다. 다음 변경이 잘못된 설명에 의존할 수 있기 때문입니다.
